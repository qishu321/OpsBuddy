# 项目协作使用指南

适用：0.17.1 Windows 桌面开发预览版，2026-10-20。

## 打开已完成的后台 Demo

正常退出旧版后，打开 `release/OpsBuddy/OpsBuddy-0.17.1.exe`。同目录原数据保留，预置演示自动导入并选中。左侧项目名「多 Agent Demo · 办公待办」，主会话「办公待办看板 · 多 Agent 演示」。主会话「编排画布」或「工作流 → 项目协作 → 查看编排」可查看前端、Go 后端和审阅三位成员的真实依赖与执行记录。

右侧先显示最终3个源码文件，点击「本机运行」编译并打开交互预览；「停止」结束服务。导入本身不调用模型或运行代码，也不创建 ZIP。后续可在「项目 → 导入项目」选择 `.opsbuddy-project.json` 包；同一包重复导入会打开原项目，不另建副本。当前导入范围是已结束的代码协作，不包含未完成任务、外部知识库、定时任务或模型凭据。

## 开始一次协作

在项目主会话输入目标、选模型和明确引用的材料，从输入框「更多任务选项 → 派发子任务」打开协作入口。默认「主模型制定计划并执行」；选择最终交付格式后点「协作并执行」。本次发送权限同时用于规划、成员执行、审阅与最终汇总，不为普通子步骤逐次确认。

主模型会真实请求结构化计划，主会话显示规划任务、计划摘要、依赖、成员模型、状态、真实任务/文件和错误。无效 JSON（包括 JSON 后附加其他内容）、环、未知节点、不可用连接、越界输入、未具备能力或超限计划会明确报错，不用固定角色模板替代模型规划。

## 手动指定分工与模型

切换「手动编辑计划」，可调整职责、任务、模型连接、交付类型、验收条件、依赖以及本次已选材料/技能的子集。模型选择为空表示沿用主模型；角色和模型不是同一概念。应用不强制任何供应商或 Astra。代码节点须列出负责的具体相对文件路径，例如 `index.html`、`main.go`、`go.mod`，不支持通配符。

自动计划必须包含一个终端审阅者，依赖覆盖全部工作节点（允许传递依赖）。手动计划允许不设独立审阅者，面板会提示“未设置独立审阅”；需要验收闭环时保留 reviewer。分析与审阅默认会话文本/结构化内容；只有显式文件节点生成 Office 或 Markdown 文件。审阅记录区分“首次审阅”和后续返工审阅。

提交后保存计划 v1、模型连接、技能正文/版本/哈希、输入和项目约束快照；修改设置不会改变已提交任务。主模型自动规划不能在执行中重新委派下一级。

## 查看画布和调整运行中的计划

主会话「协作小队 → 编排画布」，或「工作流 → 项目协作 → 查看编排」，均打开同一个协作计划。画布直接显示真实成员、模型、依赖和执行状态，不另起一套工作流运行。

需要调整时点击「暂停并调整」。应用先取消本轮未完成的请求并等待收尾；收尾期间不能修改或重新派发。随后可以添加/移除成员，修改职责、模型、任务、交付类型、验收条件和代码文件职责；连线或右侧勾选上游成员都可修改依赖，选中成员间连线按 Delete 可删除依赖。材料和 Skill 仍限定在原提交快照内，新增资料请创建新的协作。

点击「保存计划」生成下一版本，然后「继续执行」。受影响的节点及原图、新图的关联下游重跑，独立分支的成功结果复用。旧计划、任务和文件保留；循环依赖、未知节点、越界材料或不完整的审阅覆盖会明确报错，不会提交半张有效的图。版本冲突要求刷新后重试。最多保存 20 次调整，返工和重试上限不会因编辑或恢复而清零。

## 中断后的恢复

暂停或桌面退出后，在主会话或编排画布点击「继续执行」。应用保留已完成成员、待追加要求、审阅记录和模型配置快照，恢复尚未完成的步骤。规划或汇总中断也可以继续，已完成的独立分支不重跑。旧版本缺少必要快照时会说明原因，要求新建协作。

「重启后自动继续」默认关闭，可在派发窗口或运行中的协作小队单独开启。仅桌面退出导致的中断会自动恢复；主动暂停、整组停止和已经完成的组不会在重启时重放。未完成的模型请求会重新发送，可能再次计费；不能保证供应商侧只处理一次。模型连接被删除、地址或模型标识被修改时停止恢复，不静默切换到新端点；密钥从当前加密存储重新读取，计划中不保存明文密钥。

## 依赖、返工与停止

- 最多 6 位成员、全局 3 个执行任务并发、1 层委派。规划任务和汇总也使用现有执行队列。当前上限固定，没有费用预算设置。
- 只有依赖的实际任务成功且无待执行追加要求，才派发下游。仅引用自己的历史、明确材料及声明依赖的交付；审阅者可读取其传递依赖以归责。不会读取其他项目会话。
- 节点失败最多自动重试一次，记录新任务和原错误，不更换供应商。追加要求每成员最多 7 次。普通单 Agent 任务仍不自动重试。
- 审阅必须返回 `pass`、`rework` 或 `blocked`。返工必须关联已提供的上游节点，最多两轮；责任节点及受影响下游重新执行，独立成功分支不重跑，原任务与文件保留。
- 成员行的「追加指令」在当前轮后执行，同时使相关下游失效；正在执行的相关下游取消后才重新派发。汇总或结束后在主会话继续新任务。
- 「整组停止」取消规划/成员/汇总请求，不再派发后继或返工，成功分支与文件保留。停止也可关闭暂停中的组，此后不可恢复。重启后只自动继续事先勾选该选项的中断组。
- 部分失败、阻塞、全部失败和取消分别显示。未通过完整验收时保留成功交付并列明缺口，不生成假装全部完成的汇总。

## 代码和办公成果

代码成员输出独立候选源码目录，默认打开文件树；候选不能直接运行。审阅后主任务集成保留候选源码、补启动清单等必要文件，生成最终项目目录。不同内容的同路径文件（Windows 大小写不敏感）明确报冲突；主模型也不能悄悄改写已审阅候选。冲突时原目录保留，可修改职责/要求后创建新协作。

最终集成只合并各成员最后成功的本轮候选；主动引用的旧候选是参考材料，不会被强行合并成同路径冲突。原始参考和各轮历史文件继续保留。不同本轮成员仍不能用不同内容覆盖同一路径。

最终项目复用右侧文件树、源码新版本、启动/停止、运行日志与交互预览。支持已有 Go、Node.js、Python 运行器；ZIP 仅在用户主动下载/导出时生成。Go 后端需要本机 Go 环境，默认关闭自动依赖下载。候选生成、内容审阅、服务启动是不同阶段：模型审阅不等于实际执行测试，服务就绪也不保证业务功能正确。

办公成果复用已有可编辑 DOCX/PPTX/XLSX、Markdown、文件预览和历史成果能力，不覆盖原件。复杂 Office 排版、公式重算与任意格式编辑仍受原有功能限制。

## 已知边界

不提供任意工具循环、联网研究、MCP 工具执行、自动安装项目依赖、无限委派或操作系统级代码沙箱。模型只得到显式提供的上下文；最终本机代码运行仍使用当前用户的已有运行环境。

回执展示真实请求连接、请求模型和供应商返回模型标识；供应商未返回标识时明确显示未提供。未实现完整 token/费用统计或金额预算，不推算虚假成本。自检全部使用本机模拟模型，不代表所有供应商网关或模型都已验收。
