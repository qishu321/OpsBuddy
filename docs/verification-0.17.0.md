# 0.17.0 协作画布与中断恢复验证

日期：2026-10-20。Windows 桌面版；Go 后端与现有任务队列、React Flow 画布复用。

## 本轮实现

- 主会话及当前项目工作流页均可打开真实协作图，显示成员角色、模型、依赖、状态。两处入口读取同一个 AgentGroup，不复制为第二套可运行工作流。
- 暂停后调整图：等上一轮取消请求完全收尾，才能保存计划/继续。成员、依赖、模型、任务、交付、验收及文件职责可编辑；最多六成员，后端复用原 DAG、输入和审阅校验。
- 版本乐观锁及计划历史；比较规范化 JSON 避免恢复后 nil/空列表导致无修改分支误重跑。旧图和新图一起计算影响范围，保留独立成功分支。计划调整不重置原重试/返工限额。
- 同组单协调器和请求收尾检查；暂停、退出不会被旧请求的取消回调覆盖为整组失败或丢掉待执行指令。
- 手动继续，及每组可选的重启自动继续（默认关）。恢复规划、成员、汇总阶段；主动暂停/停止不自动恢复。保留已成功成员与历史文件。连接配置变化时拒绝恢复，不重新定向请求。
- 构建默认仅输出 EXE，只有显式 `-Package` 才打 ZIP。支持带版本名的 EXE 与运行中的旧版本并存；启动脚本选择同目录最新文件版本，继续使用原 .opsbuddy 目录。

## 适用边界

运行中的修改通过“暂停 → 调整 → 继续”完成，不在旧请求尚未收尾时直接改图。原提交快照之外的材料和 Skill 需要新建协作。没有新增任意工具循环、完整费用预算或自动安装依赖。中断恢复会重新发送未完成请求，无法保证供应商侧恰好执行一次；可能产生新用量。

模型调用验证使用本机可控服务，没有读取或调用真实用户模型密钥。测试运行使用独立数据目录，保留真实桌面会话。复杂 Office 排版仍不在本轮验收范围。

## 失败与修复记录

初次受限环境测试 `.cache/agent-0170-desktop` 的 WebView2 子进程崩溃、窗口无进展而超时；只清理本轮测试 PID 99664，保留用户窗口。随后在隔离环境外重跑专用测试目录，实际桌面可正常执行。

第二次 `.cache/agent-0170-desktop-final` 已运行到协作阶段，自检在快速点击“继续”后的关闭按钮上遇到渲染时序问题。自检改为等按钮可操作或画布已经收起，再关闭；该失败不算通过证据。最终重新构建的 EXE 在上述默认、小窗口两轮中完整通过，不引用失败版本的哈希充当最终验收。

旧版本已经丢弃的待执行追加指令不能从现存数据自动复原；本轮之后的中断会保留该队列。当前未进行真实用户供应商的付费全链路调用，也未做整机资源基准测试。
