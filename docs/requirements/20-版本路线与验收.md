# 20 版本路线与验收

> 优先级更新（2026-10-15）：先稳定日常办公、模型会话，补 Markdown 正文与文件处理，再打通轻量开发和桌面内 HTML 网页预览。复杂编排、渠道和媒体后置；保留已有实现。以 [当前产品方向](../product-direction.md) 及 [31 开发与预览](31-轻量开发与网页Markdown预览.md) 为准，以下历史 R1/R2/R3 作为能力清单参考，不再要求全部前置完成。

## 发布顺序

| 阶段 | 必须交付 | 发布门槛 |
| --- | --- | --- |
| R0 技术验证 | 文件生成/预览/重算、本地执行、三类模型与 MCP 最小验证 | 确认支持矩阵、开发环境与依赖分发方案 |
| R1 办公 MVP | 工作台、项目、单 Agent、PPT/Word/Excel/PDF/文件整理、成果版本、角色、基础 Skills/插件/MCP、三类模型 | P0 验收全部通过，无越权/原件损坏/泄钥问题 |
| R2 协作与生图 | 模板化多 Agent、结构化工作流、生图、OCR、文档增强、素材检索 | 协作失败恢复、预算累计和图片交付可验证 |
| R3 媒体与进阶编排 | 视频生成、AI 剪辑、ASR/TTS、自由画布与进阶节点 | 异步作业不重复付费、工程可恢复、成片可播放 |

这是一份范围路线，不是工期承诺。人力、技术栈、供应商和测试环境确定后再估时。若调整优先级，应同时更新模块需求及发布门槛，避免首版表面包含所有入口但没有可用闭环。

## 建议开发依赖顺序

1. 任务/步骤/资产数据模型、工作目录与权限、模型适配器和最小工具执行器。
2. 单一 DOCX 场景打通输入、执行、预览、下载、继续修改和失败恢复。
3. 逐一补齐 PPT、Excel、PDF、文件整理，并完成文件质量检查。
4. 角色、Skill、插件与 MCP 复用统一注册和权限机制；接入剩余模型家族。
5. 基于已有运行器增加子任务、并行、预算汇总和工作流。
6. 媒体适配器及异步作业状态，再增加生图、视频、音频和剪辑工程。

## 平台专项验收

- 三类模型接口分别通过文本、流式、工具调用和错误场景；记录实测服务商、模型与日期。
- Skill 导入、插件安装/卸载、MCP 本地/远程连接、角色绑定各有一条完整测试链。
- 文件权限绕过、恶意工具输出、密钥泄露、模型超限、执行器崩溃等负向用例通过。
- 对话、项目和角色默认值优先级一致；历史任务配置可重现。
- 预览生成失败时正确降级；未验证结果不能被当作质量通过。

## R2/R3 验收重点

R2：三个 Agent 的分析、撰写、排版任务可协作；并行分支失败可恢复；总预算不超出配置调度边界；生图结果真实落盘并能用于 PPT；OCR 输出可追溯原页。

R3：视频生成支持重启查单、局部重做与下载恢复；剪辑计划与最终视频一致；字幕、配音可修改；取消后不新增付费作业；画布与非画布编辑使用同一工作流定义。

## 验收记录模板

每条用例记录：需求编号、应用版本、操作系统/硬件、模型/工具版本、输入样本、操作步骤、预期结果、实际结果、成果路径、截图或日志证据、通过/失败和遗留项。真实服务测试需要去除凭据与个人数据。

## 完成定义

需求被实现、关键验收用例通过、产物可打开并可继续使用、异常路径可解释、权限与预算生效、支持范围有记录，才视为模块完成。仅有页面、按钮、提示词或模拟数据不算交付。
