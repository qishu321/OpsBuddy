# 11 插件管理

## 定义

插件是能力分发与生命周期管理单位，可以打包 Skills、MCP 连接模板、角色模板、受控工具适配器及静态资源。首版不支持任意前端代码直接注入主界面，不建设插件交易市场。

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| PLUG-01 | P0 | 从本地目录/包安装，展示来源、版本、能力清单、权限与依赖后启用 |
| PLUG-02 | P0 | 校验清单、唯一标识、宿主最低版本及文件完整性；冲突时阻止静默覆盖 |
| PLUG-03 | P0 | 支持启停、卸载、查看错误和依赖；关闭插件后停止向新任务提供工具 |
| PLUG-04 | P0 | 同包资源统一注册；卸载前列出受影响角色、技能与工作流，保留用户成果 |
| PLUG-05 | P0 | 配置与密钥分离；安装不自动取得文件访问、网络授权或执行权限 |
| PLUG-06 | P1 | 版本升级、回滚、远程源及签名验证；校验哈希不等同于证明来源可信 |

## 清单约定草案

至少包含 id、name、version、description、minimumHostVersion、publisher/source、capabilities、permissions、dependencies、entrypoints。具体 schema 在开发时版本化，未知字段不自动解释为执行指令。

能力注册使用插件命名空间，避免两个插件的 `search` 或 `convert` 同名工具冲突。依赖 Skill/MCP 可直接由用户配置，也可由插件安装，但界面展示统一的资源身份和来源，避免重复安装。

## 生命周期与失败

下载/导入 → 校验 → 展示权限 → 安装 → 配置 → 启用。校验失败不留下半安装能力。升级失败可回到旧版本；有运行中的任务时使用版本固定或等待运行结束，不热替换执行代码。卸载不删除导出的用户文件，密钥是否移除需明确显示。

## 验收

安装包含一个 Skill 和一个 MCP 模板的插件，扩展页可追踪两者来源。禁用后新任务看不到工具；卸载后历史产物可继续打开。导入清单冲突、目录越界或版本不兼容的包时拒绝安装并指出原因。

依赖：Skills、MCP、工具注册、权限与本地存储。
