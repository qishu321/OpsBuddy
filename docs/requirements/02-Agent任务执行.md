# 02 Agent 任务执行

## 目标

让 Agent 在明确权限和预算内规划、调用工具、检查结果并交付。首版只需一个主 Agent，执行器需为后续子 Agent 保留统一接口。

## 功能需求

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| RUN-01 | P0 | 输入包括需求、附件引用、角色版本、模型配置、授权目录、预算与输出格式 |
| RUN-02 | P0 | 简单任务直接执行；复杂任务显示简短计划；只有缺失信息影响交付时发起澄清 |
| RUN-03 | P0 | 通过工具读取、创建、转换和校验文件；模型文本不能被当作文件生成成功的证据 |
| RUN-04 | P0 | 工具调用记录参数摘要、状态、耗时、输出引用、错误类别；敏感字段不进入日志 |
| RUN-05 | P0 | 进度以当前步骤、完成项和剩余项展示；没有可靠总量时不伪造百分比 |
| RUN-06 | P0 | 用户可停止任务；检查点允许重试失败步骤，副作用操作必须先确认真实执行状态 |
| RUN-07 | P0 | 完成前检查目标格式、文件存在性与可读性；交付摘要列出文件、修改和限制 |
| RUN-08 | P0 | 支持调用次数、运行时间与费用上限；达到限制进入等待状态并保留成果 |
| RUN-09 | P1 | 支持子 Agent、任务分支、按步骤重跑和局部成果复用 |

## 生命周期

状态：queued、running、waiting_input、waiting_approval、paused、cancelling、cancelled、succeeded、partially_succeeded、failed。

- 提交后 queued → running；澄清或授权分别进入对应等待状态，收到有效响应后恢复。
- 用户暂停或预算耗尽进入 paused；运行器重启后未完成任务进入 paused 并显示恢复检查结果。
- 停止后进入 cancelling，待本地工具收尾或确认远端状态后结束；远端不能取消时主任务可以 cancelled，但媒体子作业继续记录并提示可能计费。
- 所有要求产物通过校验才是 succeeded；存在可用产物但目标未全部满足为 partially_succeeded；无有效交付则 failed。
- 终态后的重试创建关联的新运行记录；不能覆写历史审计信息。

## 失败与恢复

网络或限流可有界重试；参数错误先修正，不盲目重发；写文件先使用临时路径，校验后提交；外部创建类调用使用幂等键或查单机制。状态未知的付费调用停在待核对状态，不自动重复购买。

检查点保存输入引用、配置版本、步骤状态和成果引用；不保存或展示模型私有思维链。UI 展示的是执行计划与操作摘要。

## 验收

1. 输入 Word 生成任务，必须产生可打开 DOCX，纯文本回复不能通过。
2. 停止长任务后不再调度新工具；已完成文件可见，未完成文件不标为成功。
3. 故意使某个转换步骤失败，重试不重复覆盖前面的有效输出。
4. 达到工具调用上限后停下，显示原因及继续选项，不发生无限循环。

依赖：模型、工具注册、成果管理、权限与运行日志。
