# 13 自定义模型与协议

## 范围假设

用户提出的“三大常用协议”暂解释为三类模型 API 家族：OpenAI-compatible、Anthropic Messages、Gemini GenerateContent。它们不是三个统一的开放标准；不同网关与服务商可能只实现部分功能。此解释待产品负责人确认。

| 接口家族 | 首版接入目标 | 兼容边界 |
| --- | --- | --- |
| OpenAI-compatible | Chat Completions 风格请求、流式输出、工具调用 | Responses 作为同家族独立适配项，P1；不自动推断所有网关支持 |
| Anthropic | Messages 风格请求、流式事件、工具使用 | 特殊头、内容块、工具结果映射独立实现 |
| Gemini | GenerateContent 风格请求、流式输出、函数调用 | 认证与内容结构独立实现；厂商专属扩展单独检测 |

以上是待实现适配范围，API 字段、错误码和端点以接入时核实的官方文档及测试服务为准。

## 功能需求

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| MODEL-01 | P0 | 用户新增提供商，选择接口家族，配置 Base URL、认证方式/Key、模型 ID 和显示名称 |
| MODEL-02 | P0 | 可选拉取模型列表；不支持列表时允许手动输入模型 ID |
| MODEL-03 | P0 | 连接测试分别验证认证、文本、流式和工具调用，按模型展示能力状态 |
| MODEL-04 | P0 | 保存视觉输入、工具调用、结构化输出、上下文上限等能力配置；区分已测、声明、未知 |
| MODEL-05 | P0 | 全局默认、项目默认、角色默认及任务临时模型可配置；任务执行前展示最终选定值 |
| MODEL-06 | P0 | 统一展示限流、认证失败、上下文超限等错误；工具调用信息不足的模型不能承担对应 Agent 任务 |
| MODEL-07 | P0 | 展示实际 usage 与可配置单价估算；未知费用显示未知，不能显示为免费 |
| MODEL-08 | P1 | 按任务能力路由及候选模型回退；跨供应商发送数据遵守授权范围 |

## 选择与回退规则

优先级：任务显式选择 > 角色配置 > 项目默认 > 全局默认。角色没有固定模型时才向下查找。运行开始保存模型配置快照，用户修改全局设置不影响正在执行的步骤。

工具调用不是把模型输出字符串直接当命令执行：执行器校验工具名、参数及权限。无工具能力的模型可用于纯文本步骤，不通过文本解析伪装可靠函数调用。上下文超限优先裁剪不必要材料/摘要；不得丢失权限边界和任务目标。

回退模型需符合用户批准的供应商范围。失败的写操作不因换模型而重发；中途更换需记录原因、模型与上下文重建过程。

## 媒体接口边界

聊天接口家族不等于生图、视频、ASR/TTS 接口。媒体采用独立 provider adapter，声明各自输入、异步状态、计费单位与取消能力；可复用凭据管理，但不强制套入聊天协议。

## 验收

三类接口各用受控 mock 验证流式、工具调用、工具结果回传和错误处理，再各完成至少一个真实服务的集成验证并记录版本。工具参数分片可正确组装，失败流不能被标为成功。密钥不进入导出配置和日志。仅完成其中一类时不得宣称三协议全部支持。
