# 19 技术边界与数据模型

## 定位

实施补充（2026-10-15）：用户已指定 Go 后端，并明确要求桌面程序。当前采用 Wails + Go + React/TypeScript，发行 Windows 独立 EXE，界面资源内嵌、请求在进程内分发。具体范围见 [实现状态](../implementation-status.md)。安装向导、签名和自动更新仍属后续工作。

本章用于保证需求可落地，不锁定具体前端框架、数据库或模型 SDK。建议采用 Windows 桌面外壳 + 本地应用服务 + 受控任务工作进程；外部模型和媒体服务通过适配器接入。若改为纯网页，需要独立本地执行桥接，不能假设浏览器可直接整理任意磁盘目录。

## 模块职责

| 模块 | 职责 | 不应承担 |
| --- | --- | --- |
| UI | 输入、配置、任务进度、成果预览、授权 | 直接拼接命令或持有明文密钥 |
| 应用服务 | 项目、角色、资产、配置与运行记录 | 长时间阻塞执行媒体渲染 |
| Agent运行器 | 规划、模型交互、工具选择、子任务组织 | 绕过统一权限直接操作磁盘 |
| 工具执行器 | 参数校验、权限、超时、资源控制、结构化结果 | 把不可信文本当作系统指令 |
| 文件工具链 | 文档/表格/PDF/媒体解析、生成与校验 | 伪造格式或跳过成果检查 |
| 模型适配器 | 三类接口映射、流式事件、工具调用与用量 | 对所有供应商宣称一致能力 |
| 扩展管理器 | Skill/插件/MCP注册、版本与依赖 | 安装即自动授予所有权限 |
| 媒体作业器 | 异步提交、查询、下载、取消与恢复 | 未查单就重复提交付费任务 |

跨模块统一使用工具注册表和资产引用；内置工具与 MCP 工具都经过同一调用边界。媒体接口单独适配，但共用任务、资产、预算与授权基础。

## 核心实体草案

| 实体 | 关键字段 |
| --- | --- |
| Project | id、name、rootDirectory、defaultModel、permissionProfile |
| Conversation | id、projectId、title、messages、archivedAt |
| Task | id、conversationId、request、inputAssetRefs、expectedOutputs |
| Run | id、taskId、parentRunId、configSnapshot、state、budget、checkpoint |
| Step | id、runId、dependencies、type、inputRefs、state、outputRefs、error |
| RoleVersion | roleId、version、instructions、modelRef、skillRefs、toolAllowlist |
| AssetVersion | assetId、version、path、hash、mimeType、sourceRefs、runId、validationState |
| Extension | id、kind、version、source、manifest、status、dependencyRefs |
| ModelConfig | id、family、baseUrl、modelId、credentialRef、capabilities、pricingConfig |
| PermissionGrant | id、scope、resource、operations、expiry、sourceDecision |
| WorkflowVersion | workflowId、version、nodes、edges、inputSchema、failurePolicy |
| MediaJob | id、runId、provider、externalJobId、idempotencyKey、state、cost、assetRefs |
| OperationJournal | id、runId、operation、beforeRef、afterRef、state、undoEligibility |

密钥只保存 credentialRef；实际凭据存放在凭据管理层。可变实体与历史版本分离，历史运行引用不可变快照。

## 调用与事件契约

工具调用最少包含 runId、stepId、toolId、schemaVersion、arguments、permissionContext、idempotencyKey。返回 status、outputRefs、summary、errorCode、retryability 和实际副作用摘要。

事件至少包括 run.started、step.started、tool.completed、asset.created、approval.required、run.paused、run.finished。事件含 eventId、runId、sequence、timestamp，前端按 sequence 去重并可在断线后补取。完成事件只能在结果与元数据提交后发布。

跨进程不追求不现实的绝对“只执行一次”；通过持久化状态、幂等键、文件操作日志和外部查单降低重复风险。未知状态必须显式展示。

## 本地目录建议

应用数据目录存配置、索引、日志、缓存；用户指定工作目录存项目输入快照与成果；每个 run 使用独立临时目录。路径规则需支持 Unicode 与长路径，禁止用模型直接提供的未经验证绝对路径作为写入目标。

## 研发前技术验证

验证 Office 文件生成与渲染、表格重算、中文字体、Windows 进程隔离、三类模型流式工具调用、MCP 生命周期、媒体任务恢复。技术验证失败时更新支持矩阵和替代路径，不以“后续解决”掩盖首版依赖缺失。
