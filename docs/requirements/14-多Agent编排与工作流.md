# 14 多 Agent 编排与工作流

## 目标与阶段

让多个专长 Agent 在同一任务中分工协作，并将稳定过程保存为可复用工作流。P1 先提供模板、结构化步骤编辑和运行视图；P2 增加自由拖拽画布及进阶节点。普通任务不要求用户先画流程图。

多 Agent 是执行组织方式；工作流是显式的步骤与依赖定义。工作流可以只有一个 Agent，多 Agent 也可以由主 Agent 动态分工。首版单 Agent 的运行记录、权限和成果模型应复用于两者。

## 功能需求

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FLOW-01 | P1 | 提供“分析表格 → 撰写结论 → 制作 PPT”和“资料整理 → 撰写 → 审校”等模板 |
| FLOW-02 | P1 | 主 Agent 拆解子任务，为每个子 Agent 指定目标、角色/模型、输入、工具与交付格式 |
| FLOW-03 | P1 | 支持顺序、并行、条件分支和汇合；汇合规则显式区分全部成功与允许部分成功 |
| FLOW-04 | P1 | 子 Agent 使用独立上下文和工作目录，通过结构化结果及成果引用交接 |
| FLOW-05 | P1 | 支持并发上限、总预算、子任务预算、超时、有限重试和取消传播 |
| FLOW-06 | P1 | 展示任务树/运行图、节点状态、耗时、输入输出、错误和最终汇总 |
| FLOW-07 | P1 | 保存工作流版本，编辑后不影响已有运行；支持从失败节点创建新运行 |
| FLOW-08 | P2 | 可视化画布支持节点拖拽、连线、缩放、撤销、自动布局与校验 |
| FLOW-09 | P2 | 支持有上限的循环、受控代码节点、审批节点和手动触发之外的定时触发 |

## 节点与数据契约

P1 节点：开始、Agent、工具、条件、汇合、结束。每个节点声明输入/输出 schema、依赖、失败策略。连线必须引用已存在且类型匹配的上游字段。开始前校验缺失输入、不可达节点、环路与没有结束节点等问题；P1 只允许无环流程。

主 Agent 的动态分工也转换成可追踪子任务：不能无限递归生出 Agent；默认最大并发建议 3、最大嵌套深度建议 2，均可在上限内调整。预算在父子运行间共享核算，避免各子 Agent 分别耗尽整份总预算。

## 协作与冲突

同一可编辑成果每个步骤只有一个写入者；并行角色各自输出独立成果，汇总步骤产生新版本。子 Agent 不继承父任务全部聊天或密钥，只获得所需输入与权限交集。审校 Agent 的意见必须关联成果位置和可验证问题，主 Agent 负责处理冲突并说明未解决项。

节点失败后，下游依赖节点停止，独立分支可按策略继续。重跑需判断输入与配置是否变化；变更影响的下游全部失效。对于外部发送/付费生成等操作，不以恢复工作流为理由自动重复执行。

## 验收

1. 三个 Agent 完成“Excel 分析 + Word 摘要 + PPT”，结果通过成果引用串联，汇总数字一致。
2. 两个独立节点并行执行，汇合后才启动排版节点；故意失败一支，按既定规则等待或部分完成。
3. 停止主任务后不再启动子任务；已运行工具按各自取消能力收尾并显示状态。
4. 预算累计达到上限时整个任务进入暂停，不允许子 Agent 继续无限消耗。
5. 工作流校验拒绝悬空引用、无界循环和越权工具；失败节点重跑不重复上游副作用。

依赖：任务执行器、角色、模型、成果管理、权限与预算。外部 A2A 联邦协议不在当前多 Agent 必需范围。
