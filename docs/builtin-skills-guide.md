# 内置 Skills（0.10.0）

OpsBuddy 桌面版内置 12 个说明型 Skill，随 EXE 交付，不需要另行安装。技能增强工作方法，不会凭空增加工具、供应商服务或执行权限。

## 技能目录

| 技能 | 用途 |
| --- | --- |
| 文档写作 | Word 报告、方案、指定范围修改与事实保留 |
| 会议纪要 | 从已有记录提取决策、行动项与未决问题 |
| 演示文稿 | PPT 叙事、每页观点与基础文字交付 |
| 表格整理 | 表头、数据类型、去重口径、编号与核对 |
| PDF 处理 | PDF 工作流程说明、来源页码与扫描件限制 |
| Markdown 文档 | 需求、说明、笔记与标准 Markdown |
| 网页与小游戏 | 单文件可交互页面、窄预览适配与真实状态 |
| 后端与脚本开发 | Go / Node.js / Python 项目、PORT 和相对接口约定 |
| 代码检查与排错 | 根据代码、错误和日志定位问题与小范围修复 |
| 文件分类与归档 | 分类和命名建议、真实打包范围 |
| 截图理解 | 可见信息、布局、报错与推断边界 |
| 技能编写 | 简洁的 SKILL.md 与适用场景描述 |

## 使用与管理

打开 **扩展 → Skills**，按名称、用途或分类搜索，展开“查看 SKILL.md”阅读说明。开关可停用技能，停用在重启或升级后保留。内置说明由应用维护，需定制时点击复制按钮，再修改并保存为自定义 Skill；自定义副本可编辑或删除。

任务没有手动技能引用时，程序根据实际输出类型、请求关键词及 `$skill-name` 提及选择已启用的内置技能，每轮最多 4 项。只将选择后的正文送入生成请求，无需额外请求模型进行内置技能选择。普通问候不加载无关技能。

在输入框的 **+ → Skill** 中可显式引用，有明确选择时优先使用它们，不再自动追加内置建议。旧版本的自定义专家已迁移为可选 Skill，保留关联技能与知识库；不再提供独立专家页。原有自定义 Skill/声明式插件的按需模型选择仍保留，模型先看到名称与说明，读取总额度为 4 项。

助手回复下方显示实际读取的技能，工具过程和本次任务配置可查看技能版本、正文和哈希。修改配置、停用技能或升级应用不会改写已有任务的冻结快照。

## 格式与边界

每个内置技能使用独立目录 `internal/app/builtin_skills/<name>/SKILL.md`，具有 name、description 的 YAML frontmatter 和简短 Markdown 正文。文件通过 Go embed 编入 EXE，已有工作空间启动时补充目录；自定义技能、角色、模型和历史文件保留。

这套结构参考 [OpenAI Skills 文档](https://developers.openai.com/plugins/concepts/skills) 及 [Codex 按需加载方式](https://developers.openai.com/blog/skills-agents-sdk)，内容按 OpsBuddy 的实际工具范围重新编写。没有复制需要 Codex 专用工具或外部付费服务的整套执行指令。

当前是说明型 Skill，不执行 scripts、不自动读取外部 references/assets，也不完整实现 Codex 的工具循环。图片理解仍取决于模型的视觉输入能力；会议纪要处理已有文本，不能录音转写；PDF 和文件整理的本地固定操作不调用模型，也不会假称已读取模型技能正文。Office 不新增公式、图表、OCR 或完整排版渲染能力。
