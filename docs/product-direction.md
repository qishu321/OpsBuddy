# OpsBuddy 当前产品方向

确认日期：2026-10-15；2026-10-16 补充后端运行需求。依据用户最新明确要求：轻量版本，常用日常办公，能够开发，包含网页预览，并支持 MD 格式。

本文是后续取舍的当前依据。历史需求保留，但其范围和优先级若与本文冲突，以本文及用户后续指示为准。记录产品目标，不代表以下能力已全部实现。

## 定位

轻量的 Windows 桌面办公与开发助手，Go 后端。用户选择自己的模型，在同一会话内处理资料、生成结果、继续修改，并在右侧查看文件或网页效果。只交付桌面应用，不另做 OpsBuddy 独立网页版。

## 核心范围

| 日常工作 | 首要闭环 |
| --- | --- |
| 模型对话 | 选择已配置模型，正常回答、继续追问，Markdown 正文可读 |
| Word / PPT / Excel | 制作与常用修改，交付可编辑文件，明确实际支持的格式与限制 |
| PDF / 文件整理 | 读取与提取、合并拆分、整理明确引用的文件，原件保留 |
| Markdown | 生成、读取、修改、格式化预览和保存 .md；源文与预览可切换 |
| 开发 | 生成和修改常用代码、HTML/CSS/JavaScript、小工具页面；查看代码、保存文件并继续修改 |
| 网页预览 | 桌面右侧直接显示生成页面，并能实际点击交互；可刷新，能区分源码与页面效果 |
| 扩展 | 插件、Skill、MCP 与多 Agent 保留；独立专家库及角色选择合并到 Skills，偏好放在项目说明与记忆中 |

主路径保持：输入要求 → 执行并显示结果 → 右侧预览 → 补充修改。以“做一个 HTML 计算器”“整理一份 Markdown 需求”“把会议内容整理成 Word”作为代表场景。

## 界面收敛

默认界面保留新建任务、会话/文件、项目、输入框与结果面板。办公/开发的常用任务可直接选择；配置项放在更多选项和设置。已有工作流、知识库、定时与记忆继续保留，但不能让用户先搭流程才能完成简单工作。

不把企业权限平台、数字员工考勤、复杂工单、庞大插件市场、完整 IDE、无限嵌套编排做成首要目标。网站自动操作、渠道、会议和媒体高级能力不作为办公与开发基础闭环的前置条件。早前音视频等需求仍留档，降低优先级，不自动删除已有数据或已实现功能。

## 两种“网页”的边界

OpsBuddy 本身仍只通过桌面窗口启动；用户生成的 HTML 或项目页面可以在窗口内预览。HTML 页面预览不是重新发布 OpsBuddy 网页版。单文件 HTML/CSS/JS 直接预览；多文件项目首批支持 Go、Node.js、Python 标准库服务与命令行运行，包含启动、停止、文件和日志。完整框架构建、依赖安装与任意工程兼容仍不在当前交付范围。

MD 是正式文件格式，不强制转 Word。预览显示标题、列表、表格、代码等；保存保持 UTF-8 和 .md 扩展名。引用文件和代码内容不能以预览为由获得桌面桥接或任意磁盘权限。

## 开发顺序

1. 稳定已有办公、会话和模型执行，补正常的 Markdown 渲染。
2. 打通 .md 文件生成/修改/源文与预览/保存，以及单文件 HTML 生成/修改/真实交互预览/保存。
3. 补常用代码文件编辑与项目文件引用，逐步增加项目运行和错误定位。
4. 在真实需求推动下完善工具循环、扩展和多 Agent；避免为参考产品的所有菜单照单增加功能。

实际实现范围以 [实现状态](implementation-status.md) 和测试记录为准；需求确认不等于交付完成。
