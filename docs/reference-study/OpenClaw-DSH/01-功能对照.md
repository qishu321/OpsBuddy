# 功能对照与缺口

这是对 OpsBuddy 0.7.0 源码与已有验收的检查；参考方向见目录 README 的一手来源。表中“参考”描述拟借鉴的原则，不代表移植完成。

| 功能 | OpsBuddy 当前情况 | 参考方向与具体改进 | 位置 / 原需求 |
| --- | --- | --- | --- |
| 桌面与输入框 | 已有单窗口、材料、默认模型、权限和更多选项 | 保持简洁；补输入草稿、Markdown、代码块、复制、重试与流式；不再通过提示词改模型身份 | src/App.tsx、SessionTools.tsx；22、30 |
| 模型 | 已有三类非流式适配、配置快照和实际接口回执；验证过一次 DeepSeek 文本请求 | 能力分别测试，文本成功不等于工具/流式/视觉成功；展示返回模型与 usage，未知项明确未知 | model.go、task_config.go；13、30 |
| Agent 执行 | 对话直出、办公 JSON 交付、局部 Word 修改；没有通用工具循环 | 优先补统一工具注册、真实调用、结果回灌、取消、步数/时间上限；保留已做好的文档工具 | tasks.go、documents.go；02、29 |
| Skills | 角色绑定，先目录后读取有限正文，有冻结快照 | 补标准目录导入、名称/描述/依赖检查、明确调用和按需加载；Skill 内容本身不等于可执行工具 | task_materials.go；10、29 |
| 插件 | 声明式技能包，不是可执行插件系统 | 借鉴 DSH 的生命周期和能力分层；新增包清单、依赖、版本、禁用及运行权限；先做受控工具插件 | http.go；11、29 |
| MCP | 仅无认证远程工具发现 | 补实际 tools/call，再做 stdio、认证、超时与进程收尾；界面分开“已连接/已发现/可调用” | mcp.go；12、29 |
| 多 Agent | 四角色分工、独立任务、三并发、审阅汇总、追加下一轮和整组停止 | 补模型发起的受控委派、成员实时进度、父子导航、不同模型和预算；现有追加不能冒充运行中指令注入 | agents.go；23、29 |
| 工作流 | 有画布、连线、条件、并行汇合、运行快照、文字与文件预览 | 将节点和普通任务接到同一执行接口；显示输入来源与输出去向；后续失败节点重跑和检查点 | workflows.go、WorkflowPage.tsx；14、29 |
| 办公文件 | DOCX/PPTX/XLSX 与 PDF 页工具可用，排版与格式保真有限 | 工具执行后检查真实文件；模板、图表、公式、图片和渲染逐项验收，不凭模型承诺完成 | documents.go、docx_revision.go；03–08 |
| 知识库 | 本地片段与关键词检索、引用快照 | 暴露为 Agent 可调用检索工具；保持来源可追溯，再评估向量、重排、OCR | knowledge.go；21、29 |
| 定时与记忆 | 持久计划、独立会话、错过策略、个人/项目记忆，应用内通知 | 借鉴调度与交付分离；增工作流触发、失败通知、运行关联；后台常驻与系统通知另验收 | schedules.go、memory.go；24、25 |
| 网站与渠道 | 尚未实现 | 在统一工具循环后接登录态浏览器工具和渠道适配器；用户登录、会话隔离与发送操作独立管理 | 26、27 |
| 语音会议 | 尚未实现 | 先真实语音输入，再转写/纪要；可用才显示麦克风，不用装饰按钮代替能力 | 28 |
| 图片/视频/剪辑 | 尚未实现，只有路线描述 | 统一异步作业：提交、进度、远端状态、取消、下载、结果预览；视频剪辑需真实时间线/渲染工具 | 15–17 |

## 优先判断

先补工具循环与能力检测，再让 MCP、插件、多 Agent、工作流共用它。否则继续增入口只会增加“界面显示支持、任务却调用不了”的问题。会话内容渲染与输出检查同步补齐，后续按原定网站、渠道、语音顺序推进。
