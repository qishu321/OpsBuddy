# 实施顺序与验收

状态：调研与需求整理完成，下面各批尚未实现。当前发行版仍是 0.7.0。

## 批次 A：补齐已有任务体验与真实 Agent 基础

1. 完成 Markdown 和可读错误、草稿恢复、消息复制；保证现有删除、模型默认选择和流程画布不退化。
2. 模型适配器区分文本增量、工具请求、usage 与结束原因；先验收 OpenAI-compatible，再映射 Anthropic/Gemini，未验收的协议能力不标可用。
3. Go 工具注册表 + 循环执行器；先注册已有文件读取、知识检索、办公生成与文件检查工具。
4. 会话与步骤事件持久化，实时事件由 Wails 桥接到界面；最终正文、工具结果和文件引用均可从记录恢复。

建议新增 internal/app/agent_loop.go、tool_registry.go、session_events.go，将 model.go 保留为适配层。首次存储升级需单独制定 schema v5 迁移，先验证旧实体及密钥保留；不在本次调研中更改 schema。

验收：受控模型依次调用读取、检索、生成、检查工具，调用之间收到真实工具结果；工具失败不报成功；取消后不再调度新步骤；断线或重启不重复有副作用的调用。未知工具、非法参数、循环次数和超时明确失败或等待处理。使用 mock 验证，不自动消耗用户接口额度。

## 批次 B：让既有扩展真正可用

MCP 从远程 tools/call 开始，再接 stdio 与认证；Skill 标准目录与依赖检查；插件注册/禁用/依赖与生命周期；多 Agent 和画布节点迁移到统一循环。

验收：工具发现和调用分别记录；工具禁用后新任务不能调用；角色/Skill 内容变化不改写已提交快照；子任务结果回到主任务，整组停止不遗留排队请求；普通任务与同配置流程节点行为一致。宣称兼容其他产品插件之前提供格式和运行器的契约测试。

## 批次 C：按用户已确认的第三阶段接入

网站工具 → 飞书/钉钉 → 语音输入与会议。定时任务、记忆和工作流同时复用新的执行器，不把已存在的第二阶段功能重新做一遍。

验收：浏览器只操作用户确认的登录会话；渠道按身份和工作区路由；会议录音有开始/停止与真实转写；定时任务区分执行成功和通知成功。后台常驻、开机启动、系统通知分别提供明确开关和验收。

## 批次 D：媒体与高级办公

先图片生成/编辑，再视频异步作业与剪辑；同时完善 Office 模板、公式、图表和渲染检查。没有供应商配置时展示未连接，不生成伪结果。

验收：每个媒体作业关联真实远端 ID、进度/失败、产物和费用信息；状态不明不重复付费提交。Office 使用实际软件或独立渲染器检查版式；结构检查不能冒充渲染检查。

## 共用发布门槛

每批维护实现状态、用例与限制。桌面默认与最小窗口检查会话、画布、工具轨迹和结果预览；UI 只给已通过执行链路的能力显示可用。文档改动不等于功能交付，不为调研修改用户流程、清空会话或更换模型。
