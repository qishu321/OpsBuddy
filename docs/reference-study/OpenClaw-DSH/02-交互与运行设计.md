# OpsBuddy 交互与运行设计

以下为 OpsBuddy 的待开发设计，不是参考产品的复刻说明。

## 一次任务应该怎样完成

用户选择已配置模型并提出目标 → 按需引用文件/知识库/Skill → Agent 直接回复或给出简短执行计划 → 调用真实工具 → 读取工具结果并继续处理 → 核对正文与实际文件 → 输出可读结果、可打开文件和明确未完成项。

模型返回工具请求后，必须由 Go 工具执行器完成操作，模型不能用“我已搜索/已保存/已检查”的自然语言替代操作。外部查询失败时保留错误和来源缺口，不编造结果。

## 会话与模型

- 输入区维持当前单块布局，常用材料入口保留；更多选项不挤占正文空间。
- 模型 ID 与供应商配置出现在选择器和任务详情；身份提问交给模型自然回答，不注入客户端品牌或规定答案。
- 请求中的 model、响应中的 model/modelVersion、用户配置名称、官方型号版本说明是不同信息；缺失字段不补造。
- Markdown 渲染支持段落、列表、表格、代码块；代码可复制。禁用原始 HTML 执行，外链经用户操作打开。
- 模型能力显示文本、流式、工具、视觉各自的已测/未测/不支持状态。失败给出具体原因。
- 待输入与正在执行的消息分开；重试有新的尝试记录。取消保留已显示正文，不伪装完整回答。

## 执行时间线与结果

每次工具调用展示名称、参数摘要、运行状态、耗时、可读结果或错误；折叠显示，不展示私有思维链。默认展示最终回答，不强制每个问答生成文件。

文件成果包含预览、另存、系统打开与所在位置；文件必须真实存在且能由相应解析器读取。Word 保留能力、PPT 图表、Excel 公式等限制按当前工具检查，不按模型话术判断。

## 四类扩展各管什么

| 类型 | 职责 | 不能混同 |
| --- | --- | --- |
| 角色 | 工作方式、目标、默认 Skill/模型 | 角色提示不是工具执行权限 |
| Skill | 任务方法、参考资源、按需读取 | 读取 SKILL.md 不等于脚本已执行 |
| 插件 | 注册受控工具、配置与界面扩展 | JSON 技能包不等于可执行插件 |
| MCP | 连接外部服务及其工具 | tools/list 成功不等于 tools/call 成功 |

工具统一经过注册表和调度接口。内置办公工具、知识检索、MCP 工具、后续浏览器及媒体工具都返回相同结构的状态、正文、来源和产物引用。

## 多 Agent 与工作流

主 Agent 可以在边界内委派、等待、追加下一轮和停止。内部子任务在主会话内分组展示，只有用户明确选择独立会话才作为普通会话出现。保留固定分工模板，补自动分工前先做好单 Agent 工具循环。

画布始终可见，并行、分支、汇合显示真实状态。普通任务和流程节点调用同一执行服务；文字输出直接显示，文件输出可预览。重跑只重跑明确选定的节点及必要下游，默认不重复远端创建/发送操作。

## 后续统一入口

定时计划引用相同任务或流程定义，执行与通知分别记录。网站、消息渠道与语音作为输入/工具/交付适配器加入；媒体生成作为可查询状态的异步工具加入。登录、鉴权、模型 Key 不写入普通会话正文。
