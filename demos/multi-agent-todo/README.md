使用 OpsBuddy 0.17 的生产编排引擎和本机已配置的 DeepSeek 模型，自动完成“制定计划 → 前后端并行 → 独立审阅/返工 → 集成 → 编译启动 → 接口验证”。不是本地模板或模拟模型生成。

全程后台执行，不操作桌面窗口，不重启 OpsBuddy，不打开浏览器。当前桌面的数据库不作为第二个 App 打开，也不会被写入；只提取稳定只读快照中的模型配置到独立演示目录，不复制用户会话/材料进入模型上下文。结束后从演示数据库移除临时复制的模型凭据。

## 演示内容

- 前端：中文办公待办界面，输入并回车新增、勾选完成、搜索、状态筛选和统计；内联 HTML/CSS/JS，零 CDN、零 npm 依赖。
- 后端：Go 标准库，提供健康检查、待办列表、新增和完成切换接口，保存到演示目录自己的 JSON 文件。
- 前后端成员分别负责 `index.html` 与 `main.go` / `go.mod`，独立审阅者检查接口和源码。审阅结果和实际运行验证分开记录。
- 动态验收：实际启动 HTTP 服务，检查页面、健康接口、新增、读取、完成、空标题、超长标题和未知 ID。

## 输出

每次执行生成独立的 `runs/日期-时间/`：

| 文件或目录 | 内容 |
| --- | --- |
| `goal.md` | 本次完整目标和接口契约 |
| `agent-plan.json` | 模型实际生成的协作计划 |
| `progress.json` | 最后执行进度 |
| `execution.json` | 去除模型密钥后的实际任务、模型回执、审阅与成果记录 |
| `project/` | 集成后的真实源码 |
| `verification.json` | 实际服务接口测试结果 |
| `runtime.log` | 实际启动日志 |
| `.opsbuddy/` | 与主桌面隔离的执行记录、候选和成果；不会与当前桌面共用状态 |

最新成功运行的位置记录在 `LATEST.txt`。失败的运行保留真实记录，不标为成功。

## 再次执行

在工程目录用 `scripts/run-agent-demo.ps1` 后台重跑，模型请求可能产生服务用量。未提供额外参数时选择已有 DeepSeek 连接；没有该连接会明确失败，不擅自改用其他供应商。需要本机 Go 环境。脚本不打开任何窗口，也不自动运行当前桌面的其他任务。

成功后源码可在其 `project` 目录用 `go run .` 运行。后端读取 `PORT`，默认 `18086`；页面由同一个 Go 服务提供。演示测试结束后服务自动停止，不常驻占用资源。
